## 1. 平台判断

### 1.1 iOS

系统集成密集：语音、Keychain、Widget、App Intents、Live Activities、商店凭证、附件权限与后台限制，适合原生适配。SwiftUI 是首选 UI；通用业务不用依赖 SwiftData 的对象图，否则跨端交换与迁移更难对齐。Apple 的官方 SwiftData 示例证明它是可选路径，不证明必须选它。[S1][S2]

建议最低系统候选 iOS 17，以覆盖交互式 Widget 的基础设计；控制中心 Controls 属于更高系统版本的可选能力，运行时探测，不提高整个 App 最低版本来满足一个 P1 入口。最低版本是**项目建议**，不是已验证的最新上架要求；App Store 的提交 SDK/Xcode 要求与 deployment target 是不同条件，上线前分别核验。

| 能力 | 候选实现与已知边界 | 本项目验证内容 |
|---|---|---|
| 本地界面 | SwiftUI + NavigationStack；Apple 示例已有 SwiftUI、Widget、Live Activities 集成 [S1] | 长文本、动态字体、VoiceOver、中文输入法、暗色与键盘布局 |
| 系统语音 | SFSpeechRecognizer/音频会话为保守候选；如评估新 Speech API，单独设版本门禁 | 麦克风/识别授权、语言支持、设备能力、系统模型、离线可用性；绝不保证所有设备离线或无限录音 |
| 持久化 | SQLite + Repository；SwiftData 备选，Apple 有实际示例 [S2] | 数据迁移、附件、备份、并发写、App Group 访问策略；FTS不默认等价于中文分词 |
| Key | Keychain，默认不跨设备同步；仅在前台AI需要时取明文 | 安装/重装、锁屏、删除与备份策略；不能把 Keychain 残留当永久设备身份 |
| Widgets | WidgetKit；App Intents 轻操作；官方示例证实交互式 Widget [S2] | app/extension共享快照或受控存储、重复点击幂等、刷新预算；不能作为常驻进程/每秒刷新源 |
| 锁屏/实况 | 锁屏 Widget / ActivityKit（Live Activities）；[S1]示例为实时订单进度 | 场景资格、用户关闭、锁屏脱敏、结束清理、无推送本地方案；展示计时不等于无限后台运行 |
| Shortcuts/Controls | App Intents；Controls 候选 iOS18+，不做 R2 前提 | 深链接参数校验、执行环境、设备锁定、权限不足回 App |
| Focus/提醒 | 持久化时间戳+暂停区间、前台重算；本地通知作提醒 | 前后台切换、进程被杀、系统时间变化；不使用音频/定位保活计时器 |
| 购买 | 官方服务端库已确认有AppTransaction专用验签；客户端系统版本与实际商店凭证仍待验证 | 付费 App 购买证明与 StoreKit 非消耗型内购的 Transaction 不是同一件事 |

**付费下载特别注意：** `Transaction.currentEntitlements` 的内购权益查询不能直接作为“用户买过这个付费 App”的唯一证明；AppTransaction/应用收据的签名、环境、bundle 与版本字段按官方当前文档核对。第二轮已从官方库确认verifyAndDecodeAppTransaction及可选appTransactionId字段，但跨设备/重装/家庭共享的标识语义尚未实证。恢复入口应匹配真实商品：付费下载通常通过商店重新下载与刷新/重验应用购买证明，不能硬套 IAP 恢复。退款通知与撤销信号是否覆盖此商品、何时可获得，须单独实证；不能假设全部等同内购 server notifications。

### 1.2 HarmonyOS

目标是原生 HarmonyOS 应用，而非旧版 Android 兼容环境；OpenHarmony 是开源技术基座，不等于华为商业 HarmonyOS，也不能代表 AppGallery/IAP、商业 ASR、实况窗或开发者资质。OpenHarmony 文档用于研究 ArkTS/ArkUI、数据库、安全存储和卡片设计；商业可用范围必须回到华为正式 SDK/API 与真机验证。

版本建议：先用 **HarmonyOS 5.0 / API12 及以上作为候选基线** 做能力表；最终最低版本由选定商用 SDK、ASR、安全存储、支付及实际设备覆盖决定，不能因为某个 OpenHarmony master 示例可编译就宣称商业系统全部支持。卡片高级交互等更高 API 能力仅作可选增强。

| 能力 | 已读资料与技术建议 | 待验证/降级 |
|---|---|---|
| 界面/生命周期 | ArkTS + ArkUI + Stage；卡片独立于 UIAbility | ArkTS 语言与包约束不等于完整 TypeScript/Node 运行时，不能直接移植 npm SDK |
| 数据库 | relationalStore 基于 SQLite，支持事务、索引等；文档有读写并发、结果集与单记录大小边界 [S4] | API按实际版本核对；附件落文件；批量/分页；两端共享逻辑模型，不假定 SQL/扩展完全一致 |
| ASR | 优先验证商用 Core Speech/SpeechRecognizer 能力与系统版本 | OpenHarmony AI 目录中未找到可直接证明目标商用语音能力的材料；不能据此说“不支持”，也不能承诺免费离线。测模型安装/中文/网络/权限，失败保留文字入口并验证替代 ASR |
| Key安全 | Asset Store Kit 针对短敏感数据；HUKS 管理加密密钥 [S5][S6] | 新增资产接口说明SECRET为1–1024字节（按UTF-8字节数校验），超长 Key/组合凭证采用 HUKS 管理密钥+加密文件；逐一验证 API/上限/锁屏/卸载行为 |
| 服务卡片 | ArkTS 卡片要求 ArkUI；可用模块、HAR/HSP、native加载受限 [S7] | UI不能直接复用 Flutter 页面；完整 AI/ASR 在 App 内，卡片调用轻量业务动作 |
| 卡片更新 | postCardAction 与 updateForm，独立数据传输，主动/周期等更新模式 [S8] | 不能假定刷新时刻严格实时；显示更新时间与快照；不在卡片里运行整套业务/数据库/LLM |
| 专注计时 | 依据持久化时刻恢复，通知提醒 | 长时任务与实况窗资格须核验；普通待办计时不假定能申请常驻后台 |
| 实况窗 | 商用场景/权限/API待核验，不能用 OpenHarmony liveform 等同证明 | 不满足准入条件则仅保留通知/桌面卡片，不阻塞 R2 |
| 购买 | 应用市场地区/品类、付费下载与 IAP 分开验证 | 本次未确认 ¥3 付费下载能否为目标开发者与地区配置；不使用 Android/HMS旧文档代替原生商业验证 |

**安全存储注意：** HUKS 的“密钥对象”不是任意字符串密码箱。BYOK 的 API Key 若放加密文件，应由 HUKS 管理的密钥执行加解密；不能将 API Key 当加密算法密钥随意导入。文档中的硬件安全描述依赖设备实现，产品不能宣称绝对无法提取。

## 2. 客户端技术方案比较

| 方案 | 复用收益 | 本项目主要代价 | 判断 |
|---|---|---|---|
| SwiftUI + ArkUI 双原生 | 共享协议/规则向量/交互设计，平台适配最直接 | 双端 UI 与部分领域代码分别实现，需跨端一致性回归 | **默认推荐**，M00后冻结 |
| Flutter + 鸿蒙适配发行版 | 大量 UI/Dart 可复用 | 官方上游平台表未列 HarmonyOS [S3]；鸿蒙发行版需单独验证 engine/SDK/插件/签名；两端卡片仍原生 | 团队已有成熟鸿蒙 Flutter 发布经验时再选；不能只验证 Todo 页面 |
| React Native + RNOH | TS业务代码可共享较多 | 官方将 OpenHarmony列为 out-of-tree 独立维护平台 [S9]；原生模块/新架构/JS运行时/插件版本有兼容成本 | TS团队可做有时间盒 Spike，不据“社区支持”视为全部 SDK 可用 |
| KMP + 原生 UI | 理论可共享领域/网络/存储逻辑 | 本次未核验 HarmonyOS 目标的官方稳定支持和发布链路；需独立桥接与工具链维护 | 暂不作为进度前提 |
| Rust/C++共享核心 + 原生 UI | 规则/解析可共享、性能明确 | FFI、ABI、编译、调试和团队学习成本；卡片 native 加载受限 [S7] | 规则规模扩大且有测量收益后再考虑 |
| WebView/混合网页壳 | 内容编辑复用高 | 原生权限、密钥隔离、系统入口、性能/审查及 JS bridge 成本 | 可选 Markdown编辑局部组件，不作为整体架构 |

Flutter 上游文档在 master/main 中的版本数字可能是下一版内容；本次只据其平台列表判断“未列 HarmonyOS”，不把页面中的数字写成已发布 SDK 要求。同理，OpenHarmony master 的 API20/21 功能不能直接回填候选 API12 的能力表。

若希望推翻双原生建议，替代方案必须在同一两周时间盒完成：双端真机安装、数据库迁移、Key安全存储、系统ASR、BYOK SSE与取消、购买凭证、原生卡片；形成发行版/依赖版本表、维护主体、许可证与回退成本。只节省页面代码不足以通过架构门禁。

## 3. 相关技术研究与推荐

### 3.1 Local-first与搜索

SQLite 关系模型符合任务、依赖、项目与追加日志，协议层固定字段与迁移。iOS 可选经过维护验证的 SQLite wrapper，HarmonyOS 通过 relationalStore；共享 Schema 的逻辑语义，不要求每条 DDL 完全同文。

V1 先关键词搜索+分页+原记录定位；FTS/tokenizer 需分别探测，中文分词不能仅凭“SQLite支持FTS”推断。语义搜索和向量库是后续模块，Task Memory 先用当前任务的有界上下文与来源引用即可。

备份是高优先级基础能力：版本化 JSON+附件manifest/hash；恢复有校验、空间估算、冲突预览与失败回滚。默认排除 Key 和录音；录音如需恢复队列，使用短期加密暂存、明确保留时长、上传失败可重试，不偷偷永久保存。

### 3.2 AI协议与模型

OpenAI 官方 Node SDK 文档展示 Responses、SSE、错误处理、可配置 timeout/retries，并明确浏览器环境的密钥风险 [S10]。这不能证明 SDK 可直接运行于 ArkTS。建议 Hosted 使用服务端 SDK/受控HTTP；移动端通过原生HTTP+自有薄协议层直连 BYOK。

- Provider能力探测不等于只调 `/models`：有些 Key 无模型列表权限。执行已披露、固定最大输出的微型请求，说明可能发生少量费用。
- OpenAI官方 API 与 compatible API 分适配器；兼容端点可仅支持 Chat Completions，不能强制 Responses、strict schema 或 tool calling。
- SSE处理分包、UTF-8多字节、截断、错误事件与取消。不可把半段 JSON 当任务提交；流式文本只作预览。
- 网络重试可能导致重复付费；显式设置超时、最大重试与费用上限，业务变更独立幂等，不能依赖 SDK 默认重试保障。
- 当前任务、项目和历史记录分级授权与长度裁剪；BYOK请求不上传到 Jarvis，Hosted只接收本次必要片段，不自建用户全库镜像。
- 不指定未经测试的默认模型。按中文理解/结构化遵循/延迟/费用/地域可用性选择一款托管模型与一款通过矩阵测试的 compatible Provider。

### 3.3 ASR与自然语言时间

语音识别与LLM是两个计费和权限边界。ASR输出“可编辑转写”，不直接写任务。先完成文字捕获模块，ASR仅作为输入 adapter，可以用固定音频逐设备回归。

相对日期解析需冻结“输入当时的设备时区和本地时间”，而非等云端返回时再计算；跨午夜、跨时区、DST、仅日期与“尽快”分开测试。LLM可识别原始时间表达，标准化与精度由日期模块负责；歧义待确认。

### 3.4 商业化与政策

本节是待核验清单，不是已获得平台许可：

1. Apple App Review Guidelines 的数字功能支付/外部授权密钥条款可能与 BYOK设计相交；需要说明用户已购买完整基础App、Key是用户第三方模型计算凭据、Jarvis不代售模型额度。这个解释不能保证审核通过。
2. 核对 AI 第三方数据传输披露与同意要求、App Privacy/Privacy Manifest、隐私用途说明及实际使用的 SDK；不能用设置页一段总说明代替具体数据流同意。
3. 华为原生平台分别核验付费应用、IAP、退款、购买凭证、隐私与服务卡片/实况窗准入；确认开发者主体、首发地区和价格档位。
4. 大陆发行需确认应用备案及适用的隐私/数据出境与AI服务要求；选择能合法向目标地区提供服务的供应商。OpenAI-compatible只是协议描述，不代表OpenAI服务在所有地区可用。
5. 商店证据稳定标识/服务端可验证性决定匿名试用防重领方案。若不可得，需显式设计账户或调整试用策略；不得替代为设备指纹。
6. 后端仅保存试用必要主体标识、权益和费用账本，制定保留/删除周期；若有账户，提供账户及关联数据删除。监控不采集Key和任务全文。
