# 04 AI、Provider与语音：M05–M07

## 1. 数据流与权限边界

```text
原始CaptureInput先落本地
  → 构造最小授权上下文（inputId、referenceInstant、zoneId、source revisions）
  → 按用户选择的模式调用AIProvider
  → 协议完整性 / JSON Schema / 领域 / 来源校验
  → 本地草稿与不确定字段
  → 用户编辑、差异预览并确认
  → M01命令 + M02事务
```

录音、系统ASR、转写、LLM是不同能力。语音拒权或AI失败后文字始终可用；任何失败不能把原文清空。工作日志页默认带LOG_PROGRESS上下文，不以“所有自然语言都是新增Todo”为策略。

附件/笔记/网页中的内容属于不可信输入，不能改变系统规则、选择API origin、读取Key或执行命令。V1不自动抓取远程网页/附件全文，不向AI暴露文件系统工具。

## M05 Provider、transport、SecretStore

### 输入输出

```text
AIRequest {
 requestId, inputId, purpose(CAPTURE|DECOMPOSE|REVIEW|MEMORY|EXPLAIN_PLAN),
 mode(HOSTED|BYOK), providerConfigId?, schemaVersion,
 referenceInstant, zoneId, contextRevisions,
 originalText, allowedSourceRefs, contextItems[], consentVersion
}
AIEvent = Started | TextDelta | ProposalReady | Failed | Cancelled
```

NONE模式在调用前返回AI_DISABLED；不会调用任何服务。TextDelta仅用于“处理中”预览，不允许写入业务记录；只有完整ProposalReady且通过本地校验才可确认。请求后的模式/配置变动不将当前流自动迁移到新Provider。

### 能力表

`ProviderCapabilities`至少有apiStyle(CHAT_COMPLETIONS/RESPONSES)、structuredMode(STRICT_SCHEMA/JSON_OBJECT/TEXT_JSON)、streaming、toolCalling、maxInput/maxOutput、usageAccounting、supportedModelId、origin、profileVersion和verifiedAt。

服务商声明、连接测试结果和真实功能测试分别记录。一个模型测试通过不代表该服务商所有模型通过；`/models`无权限不等于Key一定无效。连接测试用用户知情的微型固定请求，不发送其笔记，明确可能产生少量第三方费用。

大陆服务商仍是待核实候选。适配器在Profile中显式选择协议路径，不猜测任意baseUrl后面都能无脑拼`/v1/chat/completions`。官方OpenAI与compatible profile分别维护；不得把Chat Completions端点请求成Responses。

### 子包与结束条件

| 子包 | 交付 | 独立演示/验收 |
|---|---|---|
| M05a HTTP/流解析 | 原生transport、增量UTF-8、SSE、超时/取消 | fake服务拆分多字节、多事件/片段、错误事件、截断EOF、dataEnd但无有效JSON、取消晚回调；资源清理 |
| M05b SecretStore | iOS Keychain、鸿蒙Asset/HUKS adapters | 测试字符串不出现在日志/DB/导出；0/1/1024/1025字节、锁屏、更新失败、删Key、origin变更 |
| M05c Provider adapter | request/response映射、Schema profile、错误映射 | 401/403/429/余额不足/模型不存在/5xx/usage缺失；JSON mode与strict分别fixture |
| M05d 设置/同意 | 配置、测试、启用、删除Key、模式显式切换 | 测试不自动启用；失败不丢旧配置；删除当前Key后进入未配置状态，不偷切Hosted |

Keychain候选`WhenUnlockedThisDeviceOnly`；不跨设备同步。AssetStore的SECRET按UTF-8计1–1024字节，随机alias只存引用；超长Key使用HUKS管理加密密钥+加密文件，不能截断/明文分片。Key只在调用所需生命周期中使用，调试器/设备攻破风险不承诺绝对消失。

### 传输策略

工程初始默认：连接超时15s、首个有效响应30s、总90s，全部可配置且不写进UI承诺。超过总时限保留原文。BYOK单次用户提案最多2次实际模型调用（初次+一次网络重试或一次结构修复，二者不能叠加）；任何重试/修复均算潜在费用。429尊重Retry-After，401/模型不存在不重试。Hosted的调用与修复预算由06强制控制，客户端不能独立补发来绕过额度。

- TLS验证开启；V1标准origin仅HTTPS；Key绑定规范化origin（scheme/host/port），跨origin重定向不得携带Authorization。
- Hosted只允许服务端上游白名单，不接受用户baseUrl防止任意代理/SSRF。
- 自定义BYOK私网/loopback不是默认模式；另立显式配置与本地网络权限验证，不能通过自动降级HTTP实现。
- APP直连不需要浏览器CORS放行，不因此允许把Key注入WebView。

## M06 文字捕获、拆解、合并

### 提案内部契约

[ai-proposal.schema.json](contracts/ai-proposal.schema.json)定义本地归一化的AI提案信封，不直接假定所有供应商支持完整JSON Schema。Provider adapter可向模型发送适配子集；完整的内部契约始终在客户端验证。

`schemaVersion=1.0`、proposalId、inputId、createdAt、intent、summary、uncertainFields、sourceRefs、operations。operations只接受CREATE_TASK / UPDATE_TASK / SET_TASK_STATUS / DELETE_TASK / APPEND_CONTENT五类白名单；不允许任意SQL、JSON Patch路径、工具代码或费用指令。一次最多50个operation；UNKNOWN允许空operations。

支持8类PRD意图：CREATE_TASK、UPDATE_TASK、DELETE_TASK、ADD_NOTE、LOG_PROGRESS、ADD_RESULT、REVIEW、UNKNOWN。intent和operation允许按明确规则对应：LOG_PROGRESS只追加WORK_LOG；ADD_NOTE只追加NOTE；ADD_RESULT只追加RESULT；DELETE_TASK只生成删除提案；REVIEW允许状态/日志/成果/新任务组合，但不存在“提案即执行”。拆解使用CREATE_TASK候选与预生成UUID，依赖由应用层可编辑拆解视图建立并检查DAG。

内部信封由Application/adapter规范化：proposalId、createdAt、inputId绑定来自本次请求；新建候选的clientEntityId由App预分配/映射，不能让模型覆盖已有实体ID。上游若返回这些字段，先检查绑定，不接受跨请求覆盖。模型协议可用局部引用，adapter一次性映射为UUID后再跑内部Schema与图校验。来源/版本字段依然要核查，不因填充了信封就视为可信。

### 本地二次验证

1. JSON语法/size/Schema；拒绝未知版本和额外执行字段；不从Markdown代码块中随意拼接半段输出当可信对象。
2. 校验inputId/request绑定、proposal是否属于当前请求、sourceRefs是否都在授权清单，拒绝模型猜测访问其他项目。
3. 任务/owner/Project可见且有效，来源是用户明确表达还是模型推断应展示；未确认推断不自动成为deadline事实。
4. expectedRevision以请求快照核对，不能被模型改写；时区/相对日期由M01解释。
5. WORK_LOG/REFLECTION的owner必须是TASK；NOTE/RESULT可用于TASK或PROJECT。Create的标题/描述与Update的每个patch字段必须有对应来源说明，不能把模型自报来源当已验证事实。intent与operations一致；冲突/UNKNOWN进入澄清UI。Task详情“完成了数据清洗”不能直接创建一条“数据清洗”任务。
6. 用户编辑、取消部分项后重新验证引用与预览；变更通过UoW提交。

工程AI输入上限默认原文20000字符、上下文按模型token预算裁剪。超过时先让用户选择范围，不静默丢弃原文；裁剪上下文保留sourceRefs与省略提示。大笔记/附件不自动全量上传。服务端仍需独立限制字节/token，字符数不是账本token。

### 子包

- M06a CaptureInput持久化、上下文选择、失败恢复；先用ScriptedProvider。
- M06b 草稿列表、字段来源/不确定标记、编辑/逐项确认；无Key也能独立演示。
- M06c 意图路由、多任务、任务/项目目标拆解、依赖预览；task patch的来源说明与字段对应。
- M06d 重复识别与合并：仅建议候选；合并展示两边资料、目标Task及引用迁移，不自动按相似标题删除旧任务。合并用单一事务命令，遇计划/依赖/日志冲突先处理，失败原任务不变。

验收：至少200条中文标注样本，≥20%留出集固定；macro-F1/日期字段正确率只统计已执行样本。初始目标0.90/95%为工程门槛，未达时改善或收缩支持范围；无确认删除/覆盖、含糊日期伪造精确截止、未提及自动Done分别作为硬失败独立计数。评测集包含否定、部分完成、任务同名、跨午夜、多任务和注入文本。

## M07 录音、ASR、转写编辑

### 接口与生命周期

```text
CaptureSession: IDLE→REQUESTING_PERMISSION→RECORDING→STOPPING→RECORDED
                 ↘ DENIED / CANCELLED / FAILED
SpeechEvent: Partial(text,segmentId) | Final(text,segmentId) | Unavailable(reason)
Transcript: segments[], userEditedText, locale, engineId, offlineMode, sourceInputId
```

音频与转写是不同数据，录音停止不表示识别结束，识别结束也不表示任务已创建。部分结果可覆盖同segment的展示值；final固定后只有明确的修订事件能修改。用户已编辑文本后晚到partial不得覆盖用户输入。

| 子包 | 输入→输出 | 独立验收 |
|---|---|---|
| M07a CaptureSession | 麦克风/权限→短期音频句柄 | 权限拒绝/撤销、重复start/stop、来电/蓝牙、导航退出与清理；不调用ASR/LLM |
| M07b ASR adapter | 系统语音会话或音频→segments | 中文/无模型/断网/噪声/超时/设备不支持；播放fixture与实际口述分别记录 |
| M07c 转写编辑/恢复 | partial/final/用户修改→CaptureInput | 部分/最终去重、取消/重录、跨段重复词、编辑不被覆盖 |
| M07d 上下文集成 | CaptureInput→M06或M04草稿 | 全局入口、Task Log入口、Review入口有不同purpose，不默认全转Todo |

### 平台路径

- iOS26：优先评估SpeechAnalyzer + SpeechTranscriber；先查isAvailable/supportedLocales和AssetInventory，再下载所需模型。设备不支持时验证DictationTranscriber或传统Speech路径，不能只检测系统版本。
- 传统SFSpeechRecognizer：按官方时长/限流边界设计短段；使用requiresOnDeviceRecognition前查支持；用户未同意云识别时，不自动将音频发云端。分段方案须验证转写缝合，1–3分钟复盘不等于单段可无限识别。
- HarmonyOS：Core Speech Kit公开说明有≤60s短模式与≤8h长模式；商用API版本、语言、模型、费用和Mate设备能力仍是适配器门禁，不作全设备离线保证。

工程保留策略：普通成功识别且用户保存转写后删除临时音频；失败/崩溃待恢复音频默认最多24h，存App私有受保护位置并在界面可删；用户取消立即排队清理。启动时执行可恢复检查与到期清理，不能保证应用从未运行时OS一定在精确24h执行删除；隐私文案应如实说明。系统ASR不返回音频文件的路径不人为复制长期录音。长期留存原录音不是V1默认功能。

完成条件：ASR真机证据与Capture→可编辑转写→提案→确认分开验收；30条安静/噪声/不同设备样本分别统计CER与端到端成功率。文字降级通过不代表语音发布标准通过。
