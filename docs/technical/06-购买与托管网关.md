# 06 商店购买、72小时托管与集成：M09–M11

本章定义可实施的协议与账本规则，不意味着两端商业SDK、¥3商品或BYOK审核已经获准。具体供应商、预算金额、商店凭证所有权/退款路径仍是生产门禁；fake只供隔离环境验证。

## M09 Purchase Entitlement

### 三个正交维度

```text
PurchaseState = UNKNOWN | VERIFIED | NOT_PURCHASED | REVOKED
TrialState = NOT_STARTED | ACTIVE | EXPIRED
AIMode = NONE | HOSTED | BYOK
BudgetAvailability = AVAILABLE | EXHAUSTED | RECONCILING
```

额度耗尽不能强行把未开始试用标为EXPIRED；BYOK不启动Hosted试用，不从Jarvis账本扣费。购买已验证与AI可用状态独立展示。用户数据读取/导出不能因模型到期、购买暂时无法联网验证而被清空。

归一化购买结果：`platform, evidenceKind, environment, appIdentity, productId?, canonicalStoreSubject?, verifiedAt, verificationStatus, revocationEvidence?, limitations[]`。字段缺失时明确UNKNOWN，不能由客户端布尔值补全“已购买”。

### 子包与门禁

| 子包 | 内容 | 真实验证要求 |
|---|---|---|
| M09a iOS | AppTransaction.shared、官方服务端验签、用户主动refresh；付费App与IAP分别处理 | 固定SDK/系统，真证据、错误签名、App标识/环境、重装、换设备、家庭共享 |
| M09b HarmonyOS | 官方购买证据/商品/恢复适配 | 商用SDK、个人主体接入、商品价格、退款/撤销与重新安装路径，不用旧Android HMS demo代替 |
| M09c 主体/重复领取 | 稳定商店标识→内部subjectId映射；证据重放与权限 | appTransactionID稳定语义已知；持有证明/设备验证方式还须实证，不能只验签后忽略拷贝凭证攻击 |
| M09d 本地状态UI | 缓存、恢复入口、未知/撤销说明 | 离线宽限行为按平台规则确认；原始证据不进任务库/普通备份 |

iOS内部候选唯一键为(platform,environment,appIdentity,appTransactionID)，存储可做带版本HMAC映射。不得hash整段JWS充当身份。ID退款后仍不变，所以它不单独代表当前付费有效；家庭成员各有ID，试用预算策略需考虑多人领取。

生产Hosted首次注册必须有“已验证且满足已确认资格政策”的购买证据与持有/绑定校验。仅让客户端生成publicKey、签一次nonce，不足以证明它拥有被复制的购买JWS；G2未解决就不开放生产Hosted。基础离线开发包可继续运行，不伪装商业验证已通过。

商店环境由服务端固定，生产拒绝XCODE/LOCAL_TESTING，不能接受客户端选验签弱模式。AppTransaction.refresh可能弹商店认证，只从用户“恢复/重验”操作触发，不后台反复弹窗。

## M10 Hosted Gateway

### 1. 服务结构与数据范围

Node.js稳定LTS + TypeScript + Fastify + PostgreSQL为默认候选，版本在服务初始化时锁定。模块同进程：identity、purchase verification、trials、budget、request jobs、provider、consent metadata。首版单体+数据库job表，不需要Redis/Kafka；部署地区、供应商和账号资质在商用接入前确认。

保存最小subject、权益、账本、请求状态；任务库/云同步不进入服务。为可靠执行，可暂存加密的单请求payload与结果，默认最长24h，完成后尽早删payload。结果过期后返回RESULT_EXPIRED，客户端保留自己的原文与已确认内容。日志只记ID/错误code/延迟/usage，不记Key、完整JWS、任务全文。

服务商密钥仅在服务端秘密配置/KMS，客户端永远没有。TLS开启；用户BYOK请求不进入此服务。subject会话token短期、可吊销，安装侧安全存储；商店购买证明、内部访问token和BYOK Key是三种不同秘密，不混用。

### 2. HTTP协议V1

所有写请求JSON，schemaVersion=1.0。成功信封`{data, requestId}`，失败`{error, requestId}`，error遵守[错误Schema](contracts/error.schema.json)。默认鉴权Bearer sessionToken；仅注册/健康探针例外。服务端对主体、App/环境、资源归属逐次校验，不能仅因知道requestId就读到结果。

| 路由 | 输入 | 输出 / 副作用 |
|---|---|---|
| POST /v1/identity/challenges | platform/appIdentity | challengeId、nonce、expiresAt；工程TTL5分钟，一次使用 |
| POST /v1/identity/sessions | challengeId、平台购买证据与已验证绑定材料 | subjectId、sessionToken、expiresAt；不启动试用；缺少生产绑定适配返回PURCHASE_UNVERIFIED |
| POST /v1/identity/sessions/refresh | 有效刷新材料 | 新短期session；幂等防重放，不凭subjectId自行续期 |
| DELETE /v1/identity/session | 当前会话 | 吊销当前会话；不等同删除账本或已用试用资格 |
| GET /v1/entitlements | 无 | 购买状态、trial、expiresAt、budget状态、serverNow、policyVersion；不返回内部Key |
| POST /v1/ai/requests | requestId、purpose、schemaVersion、授权最小context、consentVersion、modelProfileId | 202含requestId/status；事务预占后入持久job；不接受任意上游URL/模型Key |
| GET /v1/ai/requests/{id} | 主体鉴权 | status、usage状态、complete proposal/error、resultExpiresAt；重复读取不重复调用 |
| POST /v1/ai/requests/{id}/cancel | requestId | 尽力取消；202与最新status，已产生费用照实结算 |
| GET /v1/ai/requests/{id}/events | 主体鉴权，可选Last-Event-ID | 可选SSE进度，断线仍能GET重取；不是任务写入通道 |
| DELETE /v1/privacy/data | 明确用户确认与有效身份 | 删除/匿名化请求受理结果、保留例外说明与完成状态；规则见下 |

注册限流、nonce TTL、token TTL与payload限额是服务端配置。工程默认session15分钟，refresh材料安全存储且有吊销/过期策略；正式值由威胁与体验测试决定，不把token藏在普通备份。

最小请求/响应示意（合成数据，仅定义协议）：

```json
{
  "schemaVersion": "1.0",
  "requestId": "77777777-7777-4777-8777-777777777777",
  "purpose": "CAPTURE",
  "modelProfileId": "hosted-mainland-default",
  "consentVersion": "ai-transmission-v1",
  "input": {
    "inputId": "11111111-1111-4111-8111-111111111111",
    "text": "尽快整理数据",
    "referenceInstant": "2026-11-10T01:00:00.000Z",
    "zoneId": "Asia/Shanghai",
    "contextItems": [],
    "allowedSourceRefs": ["11111111-1111-4111-8111-111111111111"]
  }
}
```

```json
{
  "data": {
    "requestId": "77777777-7777-4777-8777-777777777777",
    "status": "QUEUED",
    "statusUrl": "/v1/ai/requests/77777777-7777-4777-8777-777777777777"
  },
  "requestId": "77777777-7777-4777-8777-777777777777"
}
```

后续GET返回status和serverNow；SUCCEEDED时有proposal（04内部Schema）、usageStatus(SETTLED/RECONCILING)、resultExpiresAt；失败有结构化error，未完成不返回半个proposal。input/contextItems每项有recordId/type/revision/text，服务端校验大小和声明的来源集合，客户端仍需验证其本地授权/快照。输入正文上限20000字符，总JSON默认256KiB且按模型token上界进一步缩小；不得接受客户端提高profile预算。正式接入时把这些结构写入OpenAPI并生成客户端契约测试，当前尚未声称存在可访问的API服务。

访问token采用服务端签名、固定issuer/audience、sub=subjectId、sid=sessionId、exp与scope；客户端不能自行声明更高scope或购买状态。refresh材料使用高熵不透明token、服务端仅存hash、单次轮转与重用检测；默认最长30天且可吊销。签名算法与密钥轮换在服务部署时固定，验证器不接受任意算法/空签名。

幂等：数据库唯一(subjectId,requestId)，记录规范化bodyDigest。同ID同body返回旧状态/结果；不同body返回409 IDEMPOTENCY_CONFLICT，不调用上游。单次修复如获许可是新的受预算约束子请求，带parentRequestId，不能复用已完成ID改body。

HTTP语义：400格式错误、401会话无效、403购买/试用/预算不允许（用业务code区分）、409幂等/版本冲突、422不支持的Schema或无效语义、429限流、503暂不可用。客户端不能把任意403都显示成“Key错误”。

### 3. 持久数据表（服务端，与本地表分离）

| 表 | 关键字段/约束 |
|---|---|
| subjects | subjectId、platform/app、商店身份HMAC及版本、status；商店身份唯一 |
| purchase_verifications | subjectId、证据摘要、资格政策版本、状态/时刻；原始敏感材料短期加密且不记日志 |
| trial_entitlements | subjectId唯一、startedAt?、expiresAt?、policyVersion；NOT_STARTED时两时间均null |
| budgets | subjectId、currency、limitUnits、spentUnits、reservedUnits、revision；NOT_STARTED也有独立总预算 |
| ai_requests | subjectId/requestId唯一、bodyDigest、state、reservationId、admittedAt、payload/result refs、cancelRequested、lease |
| budget_entries | entryId、reservationId、kind(RESERVE/SETTLE/RELEASE/ADJUST)、amount、usage/pricingVersion、createdAt；结算幂等唯一键 |
| sessions/challenges | subject/installation binding refs、nonce hash、expiry/revocation、attempt limits |
| operational_limits | modelProfile/price catalogue、全站预算、并发上限、kill switch及版本 |

金额用整数micro-CNY（1元=1000000单位），不使用浮点累计。外币上游成本使用固定版本汇率/取整规则折算，保存originalCurrency/originalUnits与pricingVersion，不能事后无痕重估历史账目。

### 4. 预算与执行算法

`available = limit - spent - reserved`。UNKNOWN usage保留相应预占；剩余额度不足时拒绝，不在下一请求中“先放行再计算”。

接收请求：

1. 验身份/购买/同意版本、时间、限流、模型白名单、输入与输出上限；服务端Clock权威。
2. 开事务锁subject预算与trial行，先查幂等。NOT_STARTED也执行总预算与失败请求频率限制，防止永远失败却无限花费。
3. 对上游整个调用计算成本上界reservation：包含输入、最大输出、已知推理/缓存等计费类别。没有可证明计费上界的模型不得加入受硬预算控制的生产白名单。
4. 检查主体及全站并发/预算，写RESERVE+ai_request(QUEUED)同事务提交；不会在数据库事务里等待模型。
5. Worker以数据库原子claim取得job，持久化DISPATCHING后调用上游；默认关闭SDK隐式重试。进程在发送边界崩溃时，不能因lease到期就盲目再次调用；进入USAGE_UNKNOWN并对账。
6. 上游完成→Schema/语义校验→持久化完整结果和usage结算。首次有效结果同事务设startedAt=当前服务端时刻、expiresAt=startedAt+72h，后续成功不能延长。
7. 已知实际成本≤预占时，增加spent、释放剩余reserved、写SETTLE；唯一reservation结算键保证重复回调不双扣。
8. 超时/取消/错误可能已发生费用；未知成本不自动释放，标RECONCILING并按供应商usage记录对账。确认没发送/没计费才能RELEASE；不能让用户通过取消循环绕过预算。

边界：首次成功定义为“结果完整、通过校验且可按requestId重取”，不是首token或用户第一次看到页面；有效结果保存后客户端断线不重开试用。首次Provider失败/输出无效不启动时间，但真实成本计账，可能在时间未启动时耗尽预算，界面需说明。

ACTIVE在`now >= expiresAt`拒绝新请求；到期前已准入的请求在自身超时范围内允许完成并结算，不因此延长expiresAt。额度先耗尽与时间到期分别显示。取消并不恢复时间。

价格变化/上游异常可能使实际上界假设失效：照实记账（不能截成reservation金额掩盖成本），暂停该profile、阻断新请求并告警。预算保证依赖已验证的计费边界；没有该前提不能宣传绝不超额。所有下游修复与重试均重新预占，原请求的UNKNOWN费用不被覆盖。

### 5. 状态与故障恢复

请求状态：QUEUED→DISPATCHING→RUNNING→SUCCEEDED/FAILED/USAGE_UNKNOWN。cancelRequested独立：QUEUED且确认未发送可CANCELLED并释放；已发送时尽力中断后按已知/未知usage结算。结果接收与预算结算在一个可恢复提交协议中，不允许“已返回成功但没写账”。

短期结果与密文payload使用应用级加密/KMS；对象存储写成功后DB原子引用，孤儿文件定期回收。单体首版也可将受限大小的加密结果放PostgreSQL，减少跨存储提交问题；客户端响应不得先于结果与trial事务提交。

定期任务扫描悬挂reservation、UNKNOWN请求、结果TTL；仅清理/对账，不自动补调已可能发送的请求。全站预算、模型白名单、每主体并发（默认1）、限流与kill switch都在服务端，可快速停止费用。kill switch不影响BYOK与本地数据。

### 6. 隐私删除与防重领

会话注销、删除本地数据、删除Hosted主体是不同操作。Hosted删除请求说明保留的最小购买资格/试用使用标记与法定账单信息、用途和期限；不得宣称“全部删除”同时无告知永久保留可关联身份。默认不保留用户任务正文；短期请求内容可提前删除。

若无法合法/合规保留最小防重领标记，应由产品接受重新领取风险或设计明确账户资格，不以隐藏指纹补洞。对本地基础用户不强制创建云账户。财务账单保留期限由发行地区政策确认，不在客户端硬编码为永久。

### 7. 独立工作包

- M10a：fake购买验证+会话/请求鉴权；串号读结果、过期token、nonce重放拒绝。
- M10b：FixedClock+trial/budget事务；首次失败、首次并发、边界±1ms、设备改时、额度未开始耗尽。
- M10c：持久job/幂等/取消/进程崩溃边界；fake provider可注入usage延迟和异常。
- M10d：真实受支持上游profile、实际账单/限额/kill switch对照；未验证不可上线。

`gateway-lab`在隔离数据库运行，至少20个并发请求争抢仅够一个/数个调用的额度，断言允许数、reserved/spent账平及唯一settle。单元锁测试不能替代数据库并发验证。

## M11 模式路由、隐私与整体验收

Settings组合M05/M09/M10的read models，不跨模块直接写库。展示购买、试用时间、额度状态、AIMode、Provider/Model、数据处理方；用户明确选择模式后生效。Hosted停止时提供“配置BYOK”与“继续基础功能”，不自动扣费、不自动切换。

| 当前模式/故障 | 行为 |
|---|---|
| NONE | 手动任务/笔记/计划/历史/备份可用；AI入口可解释地提示未启用 |
| HOSTED未开始/有效 | 先完成第三方数据说明与资格验证；首次成功按服务端开始 |
| HOSTED到期/额度耗尽/网关关停 | 阻止新Hosted请求，原始输入与已有内容保留 |
| BYOK有效 | 原生客户端直连所选origin；服务商费用由用户承担 |
| BYOK Key错误/删除/锁屏不可取 | 不调用Jarvis代偿，不读取其他Key；提示修复/解锁 |
| 拒绝/撤回AI传输同意 | 停止后续对应请求，保留本地编辑能力；进行中请求尽力取消并说明已传出内容无法保证追回 |

验收包：模式矩阵、过期/超额、全部AI断网、重启、敏感排除扫描、实际请求出口、两端购买/恢复和真实ASR；映射08的22项发布标准。只有整体验证通过才标R2候选，商店审核另记状态。
