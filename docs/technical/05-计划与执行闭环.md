# 05 计划、复盘、专注与上下文

## M08 基础Flow Engine

**拥有：**规则排序、阶段、时间/依赖冲突、推荐理由；**依赖：**M01纯规则；仓储与AI解释可替换为fake。M06不是硬依赖，用户手工创建的任务同样可生成规则计划。

```text
PlanInput {
 planDate, zoneId, referenceInstant,
 tasks[] {id,revision,status,deadline,estimate?,energy?,clarity?,projectId?,dependencies[]},
 availableWindows[]? | availableMinutes?, energyState?, currentContext?,
 lockedItems[], userOrderOverrides[], policyVersion
}
PlanOutput {draftId, sourceRevisions, orderedItems[], conflicts[], omittedTasks[], unknowns[]}
PlanItem {taskId,stage,durationMinutes?,startInstant?,reasonCodes[],reasonText,isLocked}
```

前置：tasks是已确认且未删除快照；可执行状态为TODO/IN_PROGRESS。INBOX/BLOCKED/DEFERRED/ARCHIVED/DONE不自动混入可执行推荐；DEFERRED需用户先主动恢复。任务优先级与执行建议顺序分别存，不重写Task重要性。

### 算法V1（确定性启发式，不承诺全局最优）

1. 校验DAG、锁定项是否仍存在、同任务是否重复；非法图不调用LLM“修复”。
2. 先保留用户已锁的位置/时间约束，检查与依赖和可用窗口是否冲突；冲突返回PLAN_CONFLICT而非静默解锁。
3. 迭代取拓扑就绪集合：前置任务已Done，或已排在本计划更前且估时支持该安排；不能用“所有依赖必须在生成计划前Done”把同日连续工作链错误排除。
4. 就绪任务先处理截止约束/延误风险，再遵循用户明确顺序；一般候选按上下文连续性、精力匹配、启动/清晰度、切换成本比较。缺少字段为UNKNOWN，不能当成“最简单”。
5. 无紧迫截止冲突时才插入5–15分钟可选warm-up；它必须对核心工作有帮助，不能在预计会导致核心任务逾期时照例先做杂事。阶段不要求四种齐全。
6. 有明确时间窗口和估时才分配startInstant；只有可用分钟数时输出容量内的顺序，无起止时刻；未知估时单列unknowns，不以0分钟塞进时间表。
7. 放不下的任务列omittedTasks并给原因/建议（拆分、用户改窗口或延期），不标成“已安排”。固定rule reasonCodes，LLM可润色但不得改顺序/约束。
8. 保存DRAFT；用户确认前不替换CONFIRMED计划。确认事务原子地使旧CONFIRMED→SUPERSEDED、当前→CONFIRMED，保留历史。

固定tie-break：deadline有效先比较风险层级及最早时刻，再比较上下文/精力/清晰度等枚举等级，最后createdAt/id；policyVersion记录排序规则。任何评分参数都是可验证产品假设，不引用心流理论作为已证实最优解。

### 子包与验收

| 子包 | 交付 | 独立验证 |
|---|---|---|
| M08a 输入/约束 | graph、锁定、日期/时区/容量验证 | 环、窗口重叠、截止在过去、未知估时、锁定冲突 |
| M08b 排序 | 无AI的PlanEngine及reasonCodes | 相同输入结果一致；重要临期任务不因低启动任务延误；前置A先于B |
| M08c 草稿/确认 | 调序/锁定/差异展示与撤销 | 旧revision计划不确认；移除Item不删Task；确认后AI不自动重排 |
| M08d 可选解释 | 本地模板先可用，AI只改说明 | 模型失败仍显示规则理由；解释不捏造估时/成果 |

`plan-fixtures`覆盖正常、不可满足、无空闲、用户锁定、同日依赖链、未知字段、跨时区。不可满足用例的成功结果是正确暴露冲突，不是强行产出满计划。用户研究比较开始行动耗时与主观干扰，不以计划接受率单独证明算法有效。

## M12 Daily Review

**拥有：**复盘输入→引用任务→状态/内容提案→确认→明日草稿；**依赖：**M01/M05/M08和Workspace接口；不需要M09/M10/M11先完成。语音接M07，文字可先独立交付。

输入：当天任务与相关日志的授权快照、reviewDate/zoneId、原始转写/文字、可用时间。输出：DailyReviewDraft、可编辑ChangeSet、引用依据、TomorrowPlanDraft。未提及任务保持原状态；部分完成不Done；同名任务多候选先澄清。

| 子包 | 独立交付 | 验收场景 |
|---|---|---|
| M12a 输入/引用 | 当天快照、文字复盘、任务匹配与歧义列表 | “论文只写了一半”“实验被权限卡住”“明天再做”；同名任务不能猜ID |
| M12b 提案页 | 原状态→拟状态、日志/成果/新任务、逐项确认 | 来源能回到原句；未提及任务不出现完成操作；可取消单项并重验依赖 |
| M12c 原子确认 | Review+TaskEvent+Log/Result+ChangeSet一起写 | 第N项失败不留下半份复盘；确认期间编辑任务触发冲突；重复提交不重复日志 |
| M12d 明日计划 | M08基于最新已确认状态生成次日DRAFT | 不把明日草稿直接变CONFIRMED；用户可编辑后另行确认 |

状态更新都需要用户确认，不仅是“有歧义”才确认；歧义项在确认前额外澄清。选“完成任务”不强迫用户必须上传成果；成果没有明确证据时留空。

复盘原子确认与次日计划确认是两个commit，避免为回滚一份计划而撤销真实进度。对“撤销整份复盘”应用原ChangeSet的补偿命令；如已有后续编辑，返回冲突并预览。撤销Review不自动覆盖后来已编辑的明日计划，后者显式操作。

独立Demo：ScriptedProvider+真实或内存Repository，固定五任务，其中一条未提及、一条部分、一条Done、一条Blocked、一条Deferred。要求五种结果均正确、输入可恢复；随后接真实模型与语音，测试通常1–3分钟完成流程（目标，不等于一次录音长度）。

## M13 Focus Session

**拥有：**本地计时与会话、进度草稿；**依赖：**Task命令与WorkLog接口；不依赖模型/通知授权/Live Activity。

状态：IDLE→RUNNING↔PAUSED→ENDED；已Ended不能resume，只能新建Session。一次只允许一个活跃Session（包含PAUSED）；开始其他任务需结束/切换确认，不能偷偷重计时间。

计时方法：进程内用monotonic clock累积运行段，不以每秒数据库写入或后台setInterval为真值。每次状态变化保存，运行中工程默认30秒checkpoint；保存boot/session marker与wall instant。恢复后：

- 同boot且可读取可靠连续时钟，按已保存锚点重建；暂停段不算。
- 重启/缺少可靠锚点/系统时间异常时，不直接把整段wall gap计成工作；进入待确认恢复，展示已确认累计与不确定间隔，允许用户补记。
- EndFocus幂等，actualDuration按Session及明确人工调整的投影重算，不能End点两次就加两遍。

结束时生成WorkLog草稿，用户确认再追加；Session可以已结束但Log尚未确认，不伪造一条历史。专注中全局Capture只把新想法存Inbox草稿，不改变当前Task或Session。

子包：M13a状态/Clock fixture；M13b持久恢复；M13c页面与结束日志；M13d可选通知/系统显示。验收包含暂停、杀进程、重启、调系统时间、写失败、重复结束、通知拒绝。通知没送达不是计时丢失的理由，系统入口被用户关闭也不结束真实Session。

## M14 Memory、Reflection、项目摘要与增强搜索

### M14a 上下文恢复

输入：单Task经授权的Objective、Notes、Log、Result、状态历史，附每条sourceId/revision；输出：上次完成、剩余工作、未解问题、建议下一步，每段带可打开的sourceRefs和不确定性。

缓存键至少包含ownerId、sourceRevisionDigest、provider/model、promptVersion、schemaVersion、授权范围版本；删除/修订原记录或撤回AI同意后不能继续展示过期缓存当最新事实。缓存不作为原始日志或任务下一步的权威字段。

步骤：确定性挑选最近/相关记录→按预算截取并显示省略→Provider→schema/来源校验→摘要草稿。无记录时提示无足够历史，不编造进展。来源被删除的缓存与全文索引随彻底删除清理。

### M14b Reflection与项目AI

Reflection支持手动保存（基础权益）与AI草稿，内容包括实际耗时、成果、困难、经验和后续行动；AI不直接改Task.actualDuration。项目进展摘要引用项目Notes、相关任务与最近日志，项目目标只能用户明确编辑。对长期未更新任务提供本地提示与可关闭的建议，不擅自延期/删除。

M14a/b是完整功能章节P0交付内容，不能被增强搜索延期连带取消。

### M14c 增强搜索（可后置）

在M04基础关键词检索上评估FTS/中文tokenizer。统一SearchHit至少含owner、recordId、recordType、snippet、matchedRange、updatedAt；点击定位原文，而非只显示模型答案。索引可丢弃重建，不持有唯一数据。V1不引入向量服务；后续语义检索另建能力与隐私说明。

独立验收：一个seed任务含修订/矛盾/已删除日志；摘要只引用当前授权记录、可以追溯并纠错、无依据内容进入uncertainty；项目摘要不改目标；重建索引后返回同样可定位结果。
