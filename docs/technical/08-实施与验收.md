# 08 单人实施顺序、工作包与验收

## 1. 开始方式

文档原始基线是TDD+Schema+示例；目前已新增M01 Swift领域包（未建立App UI工程），实际结果见[阶段报告](../implementation/M01-领域核心.md)。M01后续/另一端移植按以下顺序：读取01/02→建立fixtures与目标端纯领域包→实现实体/状态/日期→执行向量→再接M02。M00a并行检查实际宿主条件；首次原生UI实现平台在Mac/鸿蒙工具链结果明确后选择，不默认为用户已具备Mac。

单人开发按工作包顺序切换，不同时拉起两套完整UI。第一个原生端完成本地闭环后，将同契约/fixture与旅程移植到另一端；两端有独立构建/验收状态。若先对外发布单平台版本，应明确它尚未完成PRD的双端验收，不把它算完整R2。

## 3. 统一完成定义

工单文件/PR至少写：用户结果、输入/输出contract、依赖与fake、数据所有权、失败/恢复、测试/演示步骤、实际结果、迁移影响、已知限制与下一消费者。

| 层级 | 达成条件 | 不能冒充 |
|---|---|---|
| SPECIFIED | 文档/Schema/fixture定义并相互一致 | 未实现模块 |
| FAKE_VERIFIED | 实现用fake依赖通过业务用例 | 真实平台/供应商可用 |
| ADAPTER_VERIFIED | 实际DB/ASR/Key/购买/模型操作通过 | 跨模块完整用户旅程 |
| JOURNEY_VERIFIED | 当前构建端到端正常、故障、重启与权限场景通过 | 商店审核批准或新任务环境恢复 |

生产外部能力另记门禁：BLOCKED/READY；商店另记审核状态。发现门禁阻塞可以继续无关模块，不能取消原必需检查。所有验收只为当前build/platform提供证据。

## 4. 测试分层与fixture格式

- L0：契约Schema与serialization；枚举、可空、大小、未知字段与版本。
- L1：纯Domain/PlanEngine与可控Clock/ID的向量；状态、DAG、时区、revision、inverse。
- L2：真实Repository/UoW/附件/迁移；开关连接、注入写失败；不以InMemory替代。
- L3：fake HTTP/SSE/购买/ASR接口；取消、重试、权限、无效输出；以及真实PostgreSQL并发账本。
- L4：目标设备/真实服务adapter；模型token/费用、ASR语言/硬件、Key安全、商店凭证。
- L5：离线、AI、试用到期、复盘等端到端旅程及商店审核。

```text
Fixture {id, contractVersion, fixedClock?, input, initialState?,
         expectedOutput?|expectedError?, expectedSideEffects?, invariantChecks[]}
```

fixture只放脱敏/合成数据，不带真实Key、私有购买证据、身份证、客户语音。对预算、删除与状态安全用例，必须断言副作用是否发生，不能只比返回200。

## 8. 关键失败用例与发布硬门禁

- 无确认删除/覆盖=0；未提及任务自动Done=0；模糊时间伪造精确deadline=0。真实世界表现不可由小样本“零失败”保证，但已知用例有此错误不得发布。
- 任务/依赖/计划/事件批量事务失败后无半提交；过时revision与撤销冲突不能覆盖新内容。
- 迁移/备份恢复通过，文件staging与删除中断可恢复；备份/日志/崩溃报告不含植入的测试Key。
- Hosted重复/并发/取消/未知usage/进程崩溃不重复调用或释放不该释放的预算；实际成本异常不得隐瞒。
- 两端语音/购买/Key adapter、数据传输同意、地域/商用规则均有证据；未通过的入口关闭并说明，不能关闭预算/签名校验绕过。

```text

platform / OS / API / device / toolchain:

fixtureSet / fixedClock / seedData:
commands or manual steps:
expected / actual / passed-failed-skipped-unrun:
DB revisions / event counts / side effects:

privacy-secret scan / billing reconciliation (如适用):
known limits / rollback / feature flag:
result: SPECIFIED|FAKE_VERIFIED|ADAPTER_VERIFIED|JOURNEY_VERIFIED

```

数据结构变更走版本迁移；功能回退不等于删除用户库。关闭AI/系统入口的开关应可回到完整本地功能。只有文档、Schema或页面截图的工作包，不标模块开发完成。

## 10. 本次文档交付检查

在仓库根目录执行 `python3 docs/technical/tools/validate_contracts.py`。工具需要Python3与jsonschema；当前环境已具备，无需安装App依赖。它显式启用UTC毫秒时间/真实日历日期检查，不能仅凭校验器有FormatChecker就假定date-time可用。输出[交付校验记录](交付校验记录.json)。

检查范围：本地文档链接/代码围栏、两份Schema元规范、正常提案/错误示例、禁止SQL额外字段、非法UUID/日期/版本/标题、语义用例的Schema前置条件、17模块与22发布项完整性。后续原生实现仍需自己的领域与适配器测试；语义用例只验证示例结构，不执行不存在的业务代码。
