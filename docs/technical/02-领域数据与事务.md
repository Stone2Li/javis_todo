# 02 领域、数据与事务规范

## 1. 通用值与时间

- UUID：逻辑ID跨端不变，客户端生成；Entity revision从1开始，每次持久修改递增，不能用updatedAt代替并发版本。
- Instant：协议使用RFC3339 UTC字符串（带Z、毫秒）；数据库可映射64位epoch毫秒。LocalDate为YYYY-MM-DD；zoneId为IANA名称，由系统/测试时钟注入，不固定Asia/Shanghai。
- 文本：UTF-8；标题去首尾空白后1–200字符，正文默认≤100000字符，长度定义为Unicode标量而非UTF-8字节。Key存储另按字节限制。AI请求正文限制另见04。
- Duration：业务预计时长以整数分钟，已计专注时长以毫秒累计，展示时再换算。估时未知为null，0不代表未知。
- null表示已知为空，patch字段缺席表示不修改；两者不能混用。交换格式使用camelCase，SQL实现可snake_case。

Deadline为判别联合：

```text
NONE { kind:NONE, source:UNKNOWN, originalExpression:null|string }
DATE { kind:DATE, localDate, zoneId, source:EXPLICIT|INFERRED, originalExpression }
INSTANT { kind:INSTANT, instant, zoneId, source:EXPLICIT|INFERRED, originalExpression }
```

“明天”固定以捕获时referenceInstant+zoneId解释；请求跨午夜也不变。“尽快”保持NONE并保留原文，不伪造某日23:59。“明天下午”若无用户约定，只生成待确认时间窗口/不确定字段，不偷换成精确instant。仅日期截止视作该时区当天结束前，调度比较由本地日期边界计算，不固定加24小时处理DST。用户旅行后的DATE不自动改原zoneId；计划所在时区另存。

## 2. 实体与逻辑表

除不可变记录外，实体有`id, revision, createdAt, updatedAt, deletedAt?`。本地userId可为空，不强制Jarvis账号；Hosted subjectId不能写成用户全库所属身份。逻辑字段为实现规范，物理DDL需通过两端Repository测试。

| 实体/逻辑表 | 关键字段与关系 | 约束 / 索引 |
|---|---|---|
| Project | name, description, objective, status(ACTIVE/ON_HOLD/DONE/ARCHIVED), deadline | 活跃列表按status/updatedAt/id；project删除不级联清除Task |
| Task | projectId?, title, description, status, deadline, estimatedDurationMinutes?, actualDurationMs, complexity?, energyRequired?, completionCriteria?, nextAction?, completedAt? | projectId/status/deadline索引；actualDurationMs由已提交工作记录/Session规则累计，不由AI任填 |
| TaskMerge | sourceTaskId, targetTaskId, commitId, originalAssociationRefs | 源任务redirect/tombstone；仅用户确认的合并创建 |
| TimeAdjustment | taskId, deltaMs(有符号整数), reason, actor(USER), createdAt | 人工实际耗时修正；累计后不得小于0，与Session投影去重 |
| TaskDependency | taskId, prerequisiteTaskId | 复合唯一键；禁止自身/循环，引用必须有效；依赖已完成才可执行 |
| Note | ownerType(TASK/PROJECT), ownerId, content, contentType(MARKDOWN/TEXT), latestRevision | 多态owner关系应用层验证；删除owner时执行统一删除策略 |
| NoteRevision | noteId, version, content, actor, reason, createdAt | (noteId,version)唯一；可复原，内容不进入普通遥测 |
| WorkLog | taskId, focusSessionId?, content, progressSummary?, blockers?, nextAction?, source, recordedAt, correctsLogId? | 追加；修正写新记录指向原Log；taskId/recordedAt/id排序 |
| Result | ownerType, ownerId, title, description, resultType(TEXT/LINK/FILE/IMAGE), isFinal | 一任务可多阶段/最终成果；结果不是Task自动完成依据 |
| Reflection | taskId, actualDurationMs?, outcomeSummary, difficulties, lessons, followUpActions | 可多条修订记录，保留来源；不混同DailyReview |
| Attachment | storageKey?, remoteUrl?, mediaType, byteSize, sha256?, displayName, state(STAGED/READY/MISSING/PENDING_DELETE) | 文件归App沙盒；不保存外部临时picker路径当永久资源 |
| AttachmentLink | ownerType(NOTE/LOG/RESULT/PROJECT), ownerId, attachmentId | 唯一关联；引用计数/删除由应用层事务维护 |
| DailyPlan | planDate, zoneId, availableMinutes?, energyState?, status(DRAFT/CONFIRMED/SUPERSEDED), reasoningSummary, confirmedAt? | 同一localDate+zoneId最多一个当前CONFIRMED；历史不覆盖 |
| DailyPlanItem | planId, taskId, orderIndex, stage, suggestedDurationMinutes?, suggestedStart?, reasonCode[], reasonText, isLocked | (planId,orderIndex)唯一；一计划同task不重复；移除不删Task |
| DailyReview | reviewDate, zoneId, inputId, summary, blockers, tomorrowPlanId?, changeSetId, status(DRAFT/CONFIRMED) | completedTaskIds等作为已确认ChangeSet投影，不能独立写导致矛盾 |
| FocusSession | taskId, objective, state, startedAt, endedAt?, activeDurationMs, lastCheckpoint, bootId?, segmentData | 一设备最多一个RUNNING/PAUSED；暂停区间不计时 |
| CaptureInput | text, source(TEXT/VOICE), contextType, contextOwnerId?, referenceInstant, zoneId, state, temporaryAudioRef? | 失败保留原文；音频与转写分别保留策略 |
| ChangeSet | proposalId?, inputId?, source, status, snapshotRevisions, operations, previewDigest, committedId?, createdAt | 不能直接信任模型生成的snapshot版本或actor |
| TaskEvent | commitId, aggregateType, aggregateId, beforeRevision, afterRevision, operation, actor, sourceRefs, reason, inverseRef? | 与业务写同事务；审计不是全量永久事件溯源 |
| AppliedCommand | commandId, requestDigest, receipt, committedAt | 唯一；重试同ID同内容返回原receipt，不重复写 |
| ProviderConfig | providerId, displayName, origin, apiStyle, modelId, capabilityProfile, keyRef?, lastTestResult | 不存Key；keyRef不进入通用备份，导入后需重新绑定 |
| UserProfile/Settings | locale, notificationSettings, AI mode, activeProviderId?, featureFlags, workPreferences | 模型/隐私同意分开存；偏好可重置 |
| ConsentRecord | purpose, recipientOrigin, disclosureVersion, acceptedAt, withdrawnAt? | origin或数据范围变化重新确认；不是隐含的付费授权 |
| PurchaseCache | platform, verificationStatus, verifiedAt, evidenceKind, canonicalStoreSubjectRef? | 缓存非权威；原始商店凭证不在普通任务库和导出里 |
| SchemaMigration | version, checksum, appliedAt | 已执行迁移不可改写；修复增加新version |

TaskNote/TaskResult是PRD术语；实现分别用Note/Result并通过owner类型支持项目复用，不创建两套不一致的笔记模型。SQLite多态外键不能靠普通FK自动覆盖，UoW中必须检查owner存在并记录删除策略。

实际耗时投影：所有唯一ENDED Session的有效运行时长 + 人工TimeAdjustment之和；Log关联Session只展示关联，不重复加一次。用户手填总耗时转换为基于expectedRevision计算的delta；AI不能发AdjustTaskDuration，必须显式人工操作。若撤销造成负值或覆盖后续调整，报冲突而非截成0掩盖错误。

## 3. Task状态机

| 当前 | 允许目标 | 规则 |
|---|---|---|
| INBOX | TODO/DEFERRED/DONE/ARCHIVED | 整理确认后进入计划候选；直接Done仅允许用户明确确认并记录完成 |
| TODO | IN_PROGRESS/BLOCKED/DEFERRED/DONE/ARCHIVED | Blocked需原因；Done设置completedAt |
| IN_PROGRESS | TODO/BLOCKED/DEFERRED/DONE/ARCHIVED | 回TODO为主动停止/重置，不删除日志 |
| BLOCKED | TODO/IN_PROGRESS/DEFERRED/DONE/ARCHIVED | 解除阻塞必须更新阻塞原因；Done由用户确认 |
| DEFERRED | TODO/IN_PROGRESS/BLOCKED/DONE/ARCHIVED | 恢复执行不隐含改变deadline |
| DONE | TODO/ARCHIVED | 重新打开时清completedAt，保留完成事件 |
| ARCHIVED | 归档前状态 | 恢复时校验原状态；若引用已失效，提示并恢复为TODO，不隐式运行 |

INBOX→DONE作为单独`CompleteTask`显式操作允许，普通整理不自动Done。所有状态都允许独立`DeleteTask`，删除不是status枚举；deletedAt与ARCHIVED不同。AI没有特权跳过规则，用户手动也要满足数据完整性。

硬性依赖约束用于推荐/开始执行；历史导入或用户明确完成后补记已完成任务可能与当前依赖不一致，完成操作展示依赖冲突并要求明确确认，记录overrideReason，不让规则静默删依赖。开始Focus不提供该override，必须先解除冲突。

Project状态由用户显式变更：ACTIVE↔ON_HOLD、ACTIVE/ON_HOLD→DONE/ARCHIVED、DONE→ACTIVE/ARCHIVED；ARCHIVED恢复归档前状态。项目Done不自动把子任务Done，子任务全部Done也不自动改项目目标/状态。

## 4. 命令、提案与事务

命令信封：`commandId, actor, issuedAt, expectedRevisions, payload`。actor由Application授予（USER/SYSTEM），AI提案标注AI来源但不能直接作为有权限的actor。删除/批量修改/AI写入先生成ChangeSet，普通单项手动编辑的保存动作本身就是明确确认。

```text
CreateTask / UpdateTask / SetTaskStatus / AdjustTaskDuration / MergeTasks / DeleteTask / RestoreTask
CreateProject / UpdateProject / ArchiveProject / UnlinkProject
AddDependency / RemoveDependency
CreateNote / ReviseNote / AppendWorkLog / AddResult / AddReflection
SavePlanDraft / ConfirmPlan / ReorderPlan / LockPlanItem
ConfirmReview / StartFocus / PauseFocus / ResumeFocus / EndFocus
```

提案生命周期：DRAFT→PREVIEWED→COMMITTED；可转CANCELLED；提交前版本不符转STALE。UI允许编辑后必须重算校验与previewDigest。Preview token仅在本设备流程中证明用户确认了某个内容版本，不能作为服务端鉴权。

聚合边界：Task及其依赖/工作空间子记录的改变会递增Task聚合revision；项目Notes/Results改变递增Project聚合revision，Note另有自己的修订号。一个批次对同聚合的多个operation都比较提交前的同一revision，整批commit只把该聚合revision递增一次（不是第一条操作后让第二条自相冲突）。请求快照还记录显式引用的外部依赖版本；关系变更/owner删除必须在同一事务校验。AppliedCommand针对最外层批次commandId登记，子操作不单独提前提交。

提交算法：

1. 校验输入、ID与权限，计算规范化requestDigest（稳定字段排序，排除临时展示值）。
2. 开写事务；查AppliedCommand：同ID同digest返回旧receipt，同ID不同digest报IDEMPOTENCY_CONFLICT。
3. 读取并比较全部触及聚合revision，含依赖边、计划、Note的owner聚合；引用关系有变化也必须被检测。
4. 对一个虚拟“操作后快照”整体验证：任务/owner存在、状态、DAG、计划唯一性、删除引用；同批新建任务可引用同批预生成UUID。
5. 写业务数据、增revision、写TaskEvent、ChangeSet与AppliedCommand，原子commit；任一失败全部回滚。
6. 提交后通知UI、重建相关索引/缓存、发布系统快照。发布失败不撤销已成功数据库写入，下次按revision补发。

AI原始输出中的expectedRevision不是信任源。Application以发请求时保存的snapshotRevisions和当前库核对；模型伪造旧/新版本都不能取得写权限。批量确认取消勾选某操作后，必须重新检查其余操作对被移除新实体的引用。

## 5. 撤销与删除

- 撤销是新的补偿命令，不倒拨revision。只有被触及实体仍处于原commit后的预期revision时才可直接应用inverse。
- 若已有后续编辑，返回UNDO_CONFLICT，展示可重新应用的差异；不能覆盖新内容。跨实体批次全成全败，不半撤销。
- AppendWorkLog撤销标记该记录撤回并保留必要事件；不能悄悄重写另一条日志。创建任务的撤销遇到新附件/依赖时必须冲突提示。
- 普通删除进入回收区；工程默认保留30天，可立即彻底删除。用户选择“立即彻底删除”不承诺还能撤销；UI必须说明范围。
- 删除Task时，计划项移除，指向它的依赖边移除并告知，日志/笔记/结果一起进入相同删除批次，已确认计划保留历史事件。Project删除默认仅移除项目关联，保留任务/内容；若要级联删除必须单独预览确认。
- 彻底删除要清理内容、NoteRevision、审计中的正文快照/逆操作、原始转写、Memory缓存、搜索索引与无引用文件；只保留不含内容的最小技术事件。不能仅删主表却在备份/审计中继续显示原文。已导出到用户外部位置的备份无法自动远程抹除，应说明。

### 合并已有任务

MergeTasks是用户确认的单一批次，不是AI提案里的自动删除。预览固定source/target及两方revision，逐字段选择保留值；默认并集移动Notes/Log/Results/附件关联并保留original owner来源，重新计算实际耗时，不复制成双份。活跃Focus关联任务禁止合并，先结束/处理Session；已结束Session保留原Task关联来源，再按合并关系计入目标投影且只累计一次。

依赖图替换source引用为target后若产生自身边/环，拒绝并要求用户先编辑；同日计划同时包含source/target时必须在预览中显式解决保留Item/锁定/时长，不能默认排两遍。成功后source成为可重定向到target的tombstone，TaskMerge、移动与事件同事务；老深链进入目标并说明合并。源内容彻底删除与目标当前内容的归属范围需在UI说明，不能以清理源tombstone为由删掉已归目标的资料。

撤销合并沿用整批revision规则，并在后续变更时返回冲突；不承诺合并后任意编辑都能无损一键拆开。M06只推荐合并，MergeTasks由Application创建，任一引用迁移失败保留原两任务。

## 6. 存储与迁移协议

所有写操作由UoW协调，Repository不能各自auto-commit绕过批量事务。启用FK/WAL等具体配置按平台测试；索引和派生actualDuration不能靠UI各自累计。

迁移：检查schemaVersion→可恢复一致性备份（SQLite backup API或关闭连接后的安全副本，不能只复制主db遗漏WAL）→事务内执行迁移→校验记录/约束→写migration记录。失败保留旧库/备份并进入可恢复界面，禁止自动删库重建。新客户端遇未来数据库版本只读/拒绝写入，不能硬降级。

附件跨文件/DB不能假设原子：先将picker内容复制到staging并校验大小/hash，DB记录STAGED引用；rename到最终路径后置READY。崩溃后按清单重试；未提交staging可回收。文件删除先DB标PENDING_DELETE，确认无引用再unlink，失败后台重试。任何路径都不得由外部文件名直接拼接，使用UUID storageKey与目录约束。

## 7. 交换备份与导入

版本1容器：`manifest.json + data.json + attachments/<UUID>`。manifest含formatVersion、exportedAt、appVersion、schemaVersion、记录数、文件大小/hash和ID关联表。导出不含API Key/keyRef、商店证据、Hosted token、录音暂存、遥测和待执行AI请求；Provider只可导出非敏感元信息并标记需重新配置。

导出只复制确定的READY文件；STAGED等待完成或提示用户缩小范围，READY却缺失的文件导致完整备份失败并标明，不宣称已完整备份。用户明确选择仅导出元数据时在manifest记录缺失项。

备份是敏感个人资料。默认导出必须明确说明是否加密；V1至少提供显式警示的明文导出并调用系统分享，不声称容器天然加密。加密备份作为单独可测试adapter引入，密码不得放manifest或日志。

导入先解析版本、总大小上限（工程默认200MiB，可配置）、文件hash和所有引用；拒绝zip-slip、绝对路径、符号链接、重复路径与压缩炸弹。预览新增/碰撞/无法导入条目。默认不覆盖已有UUID：同内容可跳过，不同内容默认报冲突，可选择“作为副本”并一次性重映射所有关联UUID；不提供未经设计的自动合并。

在隔离暂存库完成校验，用户确认后阻止新写入、关闭读写连接并执行平台支持的可恢复切换/事务导入；失败回旧状态。导入成功后重建索引与系统快照，不恢复未结束专注为RUNNING、不执行备份中的AI或删除命令。
