# 03 本地核心模块：M01–M04

共同约定见[02](02-领域数据与事务.md)。本文列出的测试与Demo为实施要求，当前未执行。所有工作包按“接口→fixture→实现→独立演示→真实adapter→集成”交付。

## M01 领域、日期与ChangeSet

**拥有：**值对象、状态规则、依赖图校验、日期语义、命令/提案校验、撤销计划生成。**不拥有：**SQL、文件、UI、模型推理和商店SDK。

输入为明确的snapshot、command、Clock/zoneId；输出为ValidatedChanges或DomainError。所有ID、时间、排序并列规则可注入，不直接读系统全局状态。

| 子包 | 交付物 | 可独立验证 / 结束条件 |
|---|---|---|
| M01a 实体/值 | Task/Project/Deadline/Duration/Revision；序列化说明 | 合法值双向往返，未知枚举拒绝，null与缺字段含义一致 |
| M01b 状态/依赖 | transition表、DAG校验、冲突输出 | 自依赖/间接环拒绝；归档/删除/重开分别正确；明确完成的依赖override有记录 |
| M01c 日期 | parseInputExpression的结果与不确定字段；不把任意自然语言parser写死到Domain | 固定时间跨午夜/DST/时区；“尽快”无精确deadline |
| M01d 变更 | preview、validateCommit、buildInverse；revision集 | 未确认不能提交AI变化，过时版本冲突；inverse不覆盖后续修改 |

独立演示 `domain-fixtures`：读取共同JSON向量→平台领域实现→规范化JSON结果；比较语义结果而非语言对象内存布局。向量含input、fixedClock、expectedResult/error；不依赖数据库或网络。

至少包含 `D01-CREATE`、`D02-CYCLE`、`D03-DST`、`D04-VAGUE_DATE`、`D05-STATUS`、`D06-STALE_PREVIEW`、`D07-UNDO_CONFLICT`、`D08-IDEMPOTENCY_DIGEST`。它们是真规则断言，不以对象能构造成功充数。这个工作包可以在平台签名之外推进；但最终必须由实际Swift/ArkTS实现消费同组fixtures，宿主仅解析JSON不算规则通过。

失败：任何校验失败返回结构化错误，不生成部分已应用变化。协议字段升级先更新schema/测试向量，两端实现不得自行增加不同状态。

## M02 本地数据库、文件和备份

**拥有：**Repository/UoW、迁移、附件落盘、备份；**依赖：**M01接口；**不拥有：**业务页面与AI。

| 子包 | 输入→输出 | 演示与验收 |
|---|---|---|
| M02a 数据库选择/基本Repository | entity与filter→snapshot/page | 针对iOS SQLite候选/鸿蒙relationalStore分别运行同一CRUD、排序、分页与关系套件；固定工具链/锁文件/许可证 |
| M02b UoW/审计/幂等 | expectedRevisions+commands→receipt | 同批第N步失败全部不写；重复commandId不增revision；事务内命令与事件一致 |
| M02c 附件生命周期 | picker stream→STAGED/READY；unlink→PENDING_DELETE | 拷贝中断、低空间、rename失败、DB已提交但文件未就绪、重复清理均可恢复 |
| M02d 迁移 | 旧schema数据库→新schema或保留旧库 | 至少v1→v2带真实seed升级、注入失败回退；WAL场景备份不丢最近写入 |
| M02e 导出/导入 | export scope→容器；容器→预览→确认导入 | 多记录/附件hash、损坏包、冲突副本UUID重映射、zip-slip、未来版本、失败回滚 |

`repository-conformance`应可创建独立临时数据库，执行→关闭连接→重新打开验证；清理仅限测试沙盒路径。不能在用户数据目录复用测试套件。实现不能为了通过测试把持久化替换为内存对象。

数据集：小集20任务/3项目/多条日志；性能集1万任务/5万日志，附件大小在独立文件。核心断言包括外键/owner完整性、正确记录数、revision/事件一致、附件SHA256、导出不含已植入的测试Key与token。相关文件命名为fixture，明确从未使用真实凭据。

恢复UI提供错误说明、重试、导出可读数据/选择有效备份入口；数据库损坏不是自动清空数据的理由。

## M03 Todo、Project、Today与手动计划

**拥有：**四导航壳和离线任务/项目用例、Today基础显示；**依赖：**M01/M02；**不依赖：**AI、账号、麦克风、通知、购买联网。

### 用例与页面状态

| 用例 | 输入与前置条件 | 输出/交互 |
|---|---|---|
| QuickCreateTask | title、可选Project、明确日期；默认INBOX | 保存成功receipt后列表可见；输入验证不清空草稿 |
| EditTask | id、expectedRevision、patch | 更新快照；冲突展示当前/用户草稿，不能覆盖 |
| Complete/Reopen | 用户明确点击、相关依赖状态 | 写状态/时间/事件；重开保留历史 |
| OrganizeInbox | 已捕获任务、字段确认 | TODO、关联Project；不自动运行任务 |
| ManageProject | 创建/编辑/归档/解除关联 | 项目详情任务+活动；项目删除范围先预览 |
| EditManualPlan | planDate、zoneId、任务顺序/阶段/锁定 | draft→confirm；移除计划项不删除任务 |
| BrowseHistory | status/date/project、cursor | 完成/归档任务和资料可查看，空页和末页分开 |

Task表单支持复杂度、精力、完成标准、下一步和依赖，允许信息未知，不强迫每次填写全部字段。Today在无任务/无计划时给明确空状态，在无AI时使用手动计划和规则提示。四导航Review可先显示本地历史，不显示尚未实现的AI按钮或虚假成功。

未提交的表单草稿按页面实例/owner保存，导航退出给保存/舍弃选择；用户明确舍弃才能清理。列表采用稳定分页与乐观UI可回退策略：用户操作即时显示saving，commit后才显示成功；失败恢复原状态并保留输入。

### 子包

- M03a：任务/Inbox列表、CRUD、历史；先用InMemoryRepository打开页面，随后替换M02真实库。
- M03b：项目CRUD、关联和归档；不创建项目专属的第二套Task存储。
- M03c：Today与手动DailyPlan，依赖/锁定校验调用M01，不等待M08智能推荐。
- M03d：空/错误/冲突/离线状态、大字体与屏幕阅读器标签；两端有同场景清单。

### 独立验收旅程 `offline-task-journey`

关闭外部网络→创建“论文”项目→创建A/B任务→B依赖A→A加入今天手动计划→添加锁定→完成A→保存并重启→查看历史→移除计划中的B→确认B仍在任务库→重新打开A。每一步核对DB快照与事件，至少有一次磁盘写失败和一次revision冲突。无需任何AI或支付fake才能通过本地闭环。

## M04 Workspace、记录、附件与基础搜索

**拥有：**Note/Revision、WorkLog、Result的应用用例与页面；**依赖：**M01/M02，完整导航接M03；**不依赖：**模型与Focus实现。Focus关联字段可为空，Reflection/Memory由M14另加用例。

| 子包 | 实现范围 | 独立验收 |
|---|---|---|
| M04a Notes | Markdown源码编辑+受控预览，手动保存/可配置防丢草稿 | 大段中文、键盘/选择、重启草稿；修订可查；冲突不覆盖 |
| M04b WorkLog | 追加、recordedAt/source/blockers/nextAction，修正引用原log | 同时间按id稳定排序；取消不写；重复确认仅一条 |
| M04c Results/附件 | 阶段性/最终、文本/链接/图片/文件；App沙盒复制 | picker授权失效后已复制文件仍可读；缺失文件有状态；不因成果保存自动完成Task |
| M04d 历史/基础搜索 | 标题、正文关键词分页，结果携owner与原记录定位 | 中文和特殊字符、大小写规则文档化；参数绑定；删除内容不再检索到 |

Markdown渲染禁执行任意HTML/JS，不自动请求外部图片或跟踪链接；点击外链提示目标并交系统打开。若需要WebView，仅加载受控本地渲染资源，禁止宽泛JS桥和将Key注入网页。解析器的GFM支持不是富文本编辑器已完成的证据。

项目Notes/Results复用owner接口。删除或隐藏某条记录后，相关Memory缓存按source revision失效；M14尚未实现时仅发布普通LocalDataChanged。

`workspace-demo`独立以一条seed Task渲染，不必先完成全部导航。验收：2条笔记修订、3条追加日志、2个成果及附件→完成任务→重启→全文定位→撤回一次修改→损坏一个附件→显示MISSING但其余资料可用。导出后检查内容、附件和敏感排除项。
