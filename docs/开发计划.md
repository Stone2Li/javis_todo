## 1. 发布边界与需求冲突

| 版本 | 内容 | 发布定义 |
|---|---|---|
| R0 本地开发预览 | 任务、项目、工作空间、手动计划、备份 | 仅内部包，不宣传为完整 PRD 产品 |
| R1 AI 内测 | 加文字/语音捕获、拆解、基础 Flow、BYOK | 测试模型与协议，不视为商业发布 |
| R2 商业 MVP | 加商店购买验证、托管 72h、预算、隐私、安全与双端验收 | 覆盖 PRD 第 16 节全部 22 项，商店审核通过才发布 |
| R3 全部 P0 | 在 R2 基础上补齐 Daily Review、状态建议、次日计划，以及工作空间的 Reflection/Task Memory 和项目 AI 摘要 | 推荐作为对外宣传“完整工作闭环”的首个版本 |
| R4 体验增强 | Focus、增强搜索、系统入口、个性化 | 分批交付；不承诺所有系统入口两端相同 |

必须显式处理的冲突：

1. Daily Review 在 §6.5 为 P0，§14 又放在 Phase 2，§16 未要求完整复盘。默认保留为 R3 必交；若首发宣称“符合全部 P0”，首发必须包含 R3。不得静默推迟。
2. §4.2 基础版有 Focus 与搜索，但 §6/§14 标为 P1。这是权益归属与上线时间两个维度：推出后属于买断基础功能，不代表 R2 必须实现；商店文案只能列已上线功能。
3. §6.3 包含附件、Reflection、Task Memory，后两者在版本规划偏后。R2 工作空间实现 Notes/追加日志/文字、链接、图片、文件成果、历史记录；为保守覆盖功能章节 P0，AI Memory 与 Reflection 在 R3，增强搜索在 R4。R2 Markdown 采用源码编辑+预览，不做完整富文本编辑器。
4. “两端保持一致”解释为同一输入产生一致业务结果，不表示 V1 自动跨设备同步。V1 不建自有云同步；先做版本化导出/导入，禁止暗示实时互通。
5. ¥3 是目标价格，付费下载与应用内买断不是同一方案。默认优先验证付费下载；不擅自改成订阅或内购。任一商店不支持目标商品/地区价格时进入产品决策门禁。

## 2. 架构与模块化约束

### 2.1 技术基线（Phase 0 通过后冻结）

- iOS：Swift、SwiftUI、Swift Concurrency；SQLite 持久化适配（可选 GRDB，先验证维护状态与许可证）；URLSession 网络；Keychain；系统 Speech 能力按设备探测。
- HarmonyOS：面向原生 HarmonyOS 应用体系，ArkTS、ArkUI、Stage 模型；ArkData relationalStore；系统 Network Kit；安全存储优先评估 Asset Store Kit，必要时 HUKS 管理加密密钥。**不按 Android APK 或旧版兼容运行方式估算。**
- Hosted Gateway：TypeScript + Node.js LTS + Fastify（备选等价轻框架）+ PostgreSQL；单服务、单账本，首版不拆微服务。Redis 只有压测证明需要才引入。运行时与包版本在 M00 验证后锁定，不把本机现有 Node 版本当作发布基线。
- 共享：JSON Schema、OpenAPI、状态机规范、日期语义、错误码、调度测试向量、AI 评测集、设计 token。两端领域逻辑可分别实现，用同一套输入/预期输出测一致性。
- 不把 Swift/ArkTS 强行复用为同一代码库；Rust/C++/KMP 共享核心仅作为后续优化，必须有可测收益且验证鸿蒙工具链后再引入。
- AI 首版采用有界工作流，不引入自治 Agent、多 Agent 平台或向量数据库。AI 不持有数据库写权限。

### 2.2 建议目录（仅规划，本次不初始化工程）

```text
apps/ios/                    # 原生 UI、应用用例、iOS 适配器
apps/harmony/                # 原生 UI、应用用例、HarmonyOS 适配器
services/hosted-gateway/      # 购买验证、试用、预算、托管调用
contracts/                   # Schema/OpenAPI/错误码/版本兼容规则
fixtures/                    # 固定时钟、AI 样本、跨端规则测试向量
qa/                          # 验收说明、端到端场景、设备矩阵
docs/                        # 调研、ADR、阶段证据与发布清单
```

每端内部按 Domain → Application → Ports/Adapters → UI 分层。功能模块依赖领域接口，不互相导入页面、数据库表或第三方 SDK。所有模块提供 mock adapter、固定种子数据和可单独打开的演示入口。

### 2.3 核心接口

| 接口 | 责任与边界 |
|---|---|
| TaskRepository / WorkspaceRepository | 查询、事务、版本比较；UI 不拼 SQL |
| ChangeSetService | 提案→差异→用户确认→事务提交→TaskEvent；逆向变更撤销，冲突时提示，不覆盖新编辑 |
| Clock / TimeZoneResolver | 可注入时钟；明确日期、仅日期、相对日期分别处理 |
| SpeechTranscriber | 能力探测、权限、开始/取消/结束、partial/final、失败原因；不理解任务 |
| AIProvider / AITransport | 按 schemaVersion 返回建议；Hosted 与 BYOK 明确路由，禁止静默切换 |
| SecretStore | 返回 key reference；不通过普通业务模型传递密钥，不进入导出 |
| PurchaseAdapter | 平台证据→验证结果→已购买/未购买/未知/撤销；与 AI 权益独立 |
| TrialService / BudgetLedger | 服务端时钟、原子预算预占、幂等结算、额度与时间独立判断 |
| PlanEngine | 已确认任务→可解释计划；硬约束优先、无解返回冲突与调整建议 |
| SystemSurfaceAdapter | 读取展示快照、提交普通业务命令；不绕过权限和变更规则 |

### 2.4 数据可靠性

- Task/Project/Workspace/Plan 使用 UUID、revision、createdAt/updatedAt；TaskEvent 是关键操作审计，不把所有数据都改造成事件溯源系统。
- Notes 有修订；WorkLog 默认追加；PlanItem 移除不删 Task；附件以独立文件+元数据存储，不塞数据库大字段。
- 时间保存原始表达、解析时区、精度及来源。全天截止保存 localDate 语义；明确时刻保存标准化 instant，不把“明天”统一当 UTC 零点。
- 数据迁移前备份，迁移/批量确认事务化；备份导入先校验 manifest/hash/schemaVersion，再预览冲突，不直接覆盖现有库。
- 两端共用逻辑交换格式，不直接交换 SQLite 文件；语音/密钥/商店证据不混入普通个人数据导出。

## 5. 关键业务算法与安全设计

### 5.1 AI 工作流

输入持久化草稿 → 意图识别 → 结构化提取 → schema 校验 → 领域约束校验 → 展示来源/不确定字段 → 用户确认 → 事务提交。

统一结果包含 schemaVersion、intent、sourceRefs、字段来源、uncertainFields、proposedChanges。不要依赖 LLM 自报置信度决定危险操作。删除、状态变更、覆盖 Notes/计划均走确认。附件和笔记中的提示文本是数据，不能扩大 AI 权限。

Provider 能力表至少区分 Responses / Chat Completions、JSON Schema/普通 JSON、SSE、tool calling、上下文/输出限额。先支持一个明确的官方接口和一个实际通过测试的兼容服务商；自定义端点不宣称“全兼容”。结构错误最多一次有界修复，仍失败保留原文；401/余额不足不盲重试。重试次数与费用均纳入预算。

Base URL 默认仅 HTTPS，禁止携带 Key 跨主机重定向；Key 按 origin 绑定，改域名要求重新确认。为用户部署的内网端点另做显式许可与风险提示，不默认允许任意 loopback/metadata 地址。托管网关使用预设上游，不接受客户端传来的任意代理 URL，防止 SSRF。

### 5.2 Flow Engine

第一层筛掉已完成/归档任务、检查依赖 DAG、已锁时间与可用窗口；第二层处理硬截止和必须先行任务；第三层按上下文连续性、精力/清晰度/切换成本生成解释性顺序。任务时长未知时保留未知或请求确认，不伪造精确日程。

允许无 warm-up 或跳过某阶段，不硬塞四阶段。超载和矛盾依赖返回 conflicts，不给出不可执行“完美计划”。用户锁定约束优先；硬约束冲突应明确显示，不能静默重排。LLM 可补充自然语言理由，不得使规则判定结果失效。

### 5.3 72 小时与预算

- 三个正交维度：PurchaseEntitlement、TrialState、AIMode；额度耗尽是独立原因，不能伪装成时间已到期。
- iOS优先验证官方AppTransaction验签路径；appTransactionId仅为候选商店主体键，缺字段、重装、跨设备和家庭共享仍须实测，禁止用JWS全文hash作身份。生产服务端禁止XCODE/LOCAL_TESTING验签环境；刷新购买证明不得重置计时或预算。
- 服务端生成匿名主体；购买凭证与稳定标识的可行性先过 G2，不能靠 installationId、Keychain 残留或隐藏设备指纹保证防重领。若必须登录，单独告知其用于托管试用；本地基础功能不强制创建 Jarvis 账户。
- 建议“首次成功”的精确定义：Provider 结果完成且通过校验，服务端已持久化可重取结果。原子写 trialStartedAt，trialExpiresAt = startedAt + 72h；客户端断网可按 requestId 重取，不重开计时。这是待产品确认的实现解释，不是 PRD 已明确规定。
- 请求先校验购买和时间→预占最坏成本/额度→调用→按实用量结算。唯一幂等键+数据库事务保证同请求不重复计费，同主体首次请求不延长试用。
- 无可靠 tokenizer/usage 的 Provider，采用已批准的保守预占策略并限制 max output，不能先调用后发现超预算。未知状态保留占额并对账，不能立即释放后允许无限补发。
- Provider 失败也可能产生实际费用；费用账本记录真实成本，而试用成功起点仍按上述定义处理。限流、并发数、最大输入、单用户/全站预算、kill switch 必须服务端生效。
- NONE/过期/没网不阻断本地数据读取；不自动转用用户 Key。缓存已验证购买权益、未知状态宽限和撤销处理规则，须与平台政策验证后确定。

## 7. 每个模块的完成定义

1. 用一句话描述用户价值、输入/输出、边界与非目标；接口和 schema 先冻结。
2. 可在依赖 mock 的情况下独立演示；真实适配器集成通过后才声明可用。
3. 有正向、失败、重启/恢复与关键安全用例；只对风险和规则写有意义测试，不用空测试数充验收。
4. 本地写操作、AI副作用、试用账本验证原子性、幂等与冲突处理。
5. 留存环境版本、构建 SHA、测试命令/结果、评测样本版本及演示记录；未执行/跳过/失败与通过分开。
6. 双端已交付同范围，或清楚标注平台缺口；关闭功能开关后基础能力仍可用。
7. 新增隐私/费用/第三方传输有明确说明；Key、语音与内容日志按策略处理。
8. 涉及数据结构变更提供迁移与旧备份兼容证据；不能只卸载重装证明升级可用。

## 8. 产品质量与商业决策

建议首轮验收目标（非 PRD 原有数值，M00 建立基线后签定）：

- 固定基准真机/数据集：普通任务操作反馈 p95 ≤100ms，持久化 p95 ≤300ms；1万任务首屏 ≤1.5s；关键词搜索 p95 ≤500ms。同步记录冷启动/热启动、P50/P95及测量方式。
- AI 文本评测集先建 ≥200 条中文标注样本，覆盖8种意图、时间/否定/多任务/歧义；切分开发集与至少20%固定留出集。核心意图 macro-F1 ≥0.90、明确日期字段正确率 ≥95%作为初始目标。
- 高风险断言独立计数：无确认删除/覆盖=0，未提及任务自动完成=0，模糊日期伪造精确时间=0。测试通过不是对现实错误率为零的保证。
- ASR 至少30条在安静/噪声/不同设备运行，分开统计转写 CER 与端到端“可确认草稿”成功率；初期目标成功率≥90%，不以文本 LLM 准确率代替语音验收。
- 试用并发至少20个请求的预算竞争、72h边界±1ms、重复 requestId、provider超时后重试全部验证；预算越界硬断言不得靠平均成功率掩盖。
- 小规模封闭测试10–20人：捕获→开始→记录→复盘闭环、BYOK设置成功率、1–3分钟复盘可达性、主观干扰。心流排序以真实反馈验证，不宣传理论证明算法有效。
- 建议稳定性目标 crash-free sessions ≥99.5%，明确测试样本与观察周期；小样本不能宣称达到生产 SLA。

¥3 不能支持无限维护成本。试用预算按“含税售价−平台抽成−税费/退款准备−维护与服务成本”估算可补贴上限；发布前填入平台真实费率和模型账单，验证不同激活率/重试率/滥用率下是否亏损。不得凭目标售价反推无限额度。无规模化利润数据前不增加自建云同步。
